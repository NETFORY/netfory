# Oxid Mail - монорепозиторий

Защищённый почтовый клиент экосистемы NETFORY. Идентичность - BIP-39 seed (SmartHoldem),
все данные на диске зашифрованы (XChaCha20-Poly1305) и сжаты (zstd).

## Структура

```
oxid-mail/
├── ui/                    # Vue 3 + Vite + Pinia + Tailwind (см. ui/README.md - описание дизайн-системы)
├── crates/
│   ├── mail-core/         # универсальное ядро: BIP-39 identity, IMAP (rustls), SMTP (lettre), парсер писем
│   ├── mail-store/        # шифрованное+сжатое хранилище: sled + zstd + XChaCha20-Poly1305 (ключ из seed через HKDF)
│   └── oxid-bridge/       # dev/web-мост (axum, :8002) - та же командная поверхность, что у будущего Tauri-бэкенда
└── src-tauri/             # (этап 2) standalone Tauri-сборка
```

## Два режима работы (по дизайну)

1. **Web-dev (сейчас)**: UI на :3001 ходит по HTTP в `oxid-bridge` на :8002.
2. **Tauri (этап 2)**: тот же UI вызывает `invoke()` - команды идентичны маршрутам бриджа.
   Ядро (`mail-core`, `mail-store`) не зависит от транспорта, поэтому клиент соберётся
   и как standalone-приложение, и как дочернее окно NETFORY-client.

## Запуск (dev)

```bash
# 1. Бридж (Rust)
cd oxid-mail
cargo run -p oxid-bridge          # слушает 0.0.0.0:8002 (env OXID_BRIDGE_PORT)

# 2. UI
cd oxid-mail/ui
yarn && yarn dev                  # http://localhost:3001
```

## Сборка нативного приложения (Tauri) - одной командой

```bash
cd oxid-mail/ui
yarn                # один раз: ставит зависимости, включая @tauri-apps/cli
yarn app:build      # (= cd .. && tauri build) соберёт UI и нативный бинарь + установщики
```

Результат: `oxid-mail/target/release/oxid-mail(.exe)` (бинарь; target - в корне workspace)
и `oxid-mail/target/release/bundle/*` (deb/rpm/AppImage/msi/dmg - по платформе).

> Скрипт делает `cd ..` и запускает tauri из корня монорепо - CLI ищет
> `src-tauri/tauri.conf.json` в подпапках текущей директории.

Dev-режим нативного окна с hot-reload: `yarn app:dev`.

Требования на Linux: `libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev pkg-config build-essential`.
На Windows: WebView2 (обычно уже установлен) + Rust toolchain. На macOS: Xcode CLT.

Запуск из NETFORY: положите собранный бинарь `oxid-mail` рядом с бинарём NETFORY
(или в подпапку `./oxid-mail/`, или укажите путь в `OXID_MAIL_BIN`) - кнопка
«✉ ПОЧТА» в сайдбаре и карточка Mail на дашборде запустят его отдельным процессом.

## Связь со NETFORY (IPC: stdin/stdout, JSONL)

NETFORY запускает Oxid Mail **дочерним процессом с пайпами** - это одновременно
и защищённая передача секрета, и постоянный двусторонний канал:

- **NETFORY -> почта (stdin ребёнка)**, по строке JSON на сообщение:
  - `{"type":"handshake","v":1,"mnemonic":"..."}` - seed текущей сессии NETFORY.
    Уходит сразу после запуска. **Seed существует только в RAM двух процессов**:
    не попадает в argv/env/диск, не виден в диспетчере задач, канал
    родитель↔потомок нельзя перехватить извне. PIN в почте при таком запуске
    **не нужен** - авторизация уже пройдена при разблокировке NETFORY, а UI
    почты автоматически открывает сессию, минуя онбординг. В этом режиме
    (`ephemeral`) почта ничего не пишет в localStorage - при автономном
    запуске без NETFORY потребуется ввести seed или PIN как обычно.
  - `{"type":"focus"}` - повторный клик по «Почта» не плодит процессы,
    а фокусирует уже открытое окно.
- **Почта -> NETFORY (stdout ребёнка)**:
  - `{"type":"request_seed"}` - pull-запрос: почта сама просит seed
    (авто-логин при старте и кнопка **Connect NETFORY** на экране онбординга -
    если по какой-то причине авто-вход не сработал, пользователь жмёт кнопку
    и вход происходит без ручного ввода 12 слов);
  - `{"type":"handshake_ack"}` - подтверждение приёма seed;

> Фразы кошелька NETFORY могут быть **произвольными** (не обязательно BIP-39):
> при handoff валидация BIP-39 пропускается (`identity::from_secret`, деривация
> идентична NETFORY: `privkey = sha256(secret.trim())`, регистр значим).
> BIP-39 валидация осталась только при ручном вводе 12 слов в онбординге.
  - `{"type":"new_mail","count":N,"from":"...","subject":"..."}` - новые
    письма; NETFORY показывает тост (клик - открыть/сфокусировать почту).

Почему не сокеты (Named Pipes / Unix sockets): пайп родитель↔потомок не требует
аутентификации подключающегося процесса и лишних зависимостей. Если понадобится
подключаться к уже работающему клиенту извне - сокет добавится позже, а
одноразовый токен для него передадим через тот же stdin.

## Уведомления о новых письмах

Когда IMAP IDLE ловит новое письмо (или его находит периодический опрос -
каждые 20 с, работает и в свёрнутом окне), показывается **системное
уведомление** (tauri-plugin-notification) и событие `new_mail` уходит
в NETFORY по IPC-каналу.

## Объединённая сборка: один MSI = NETFORY + Oxid Mail

Из папки `frontend`:

```bash
yarn tauri:build:bonsai:mail
```

Скрипт: 1) собирает Oxid Mail (`node scripts/build-oxid-mail.cjs` -> release-бинарь),
2) копирует `oxid-mail.exe` в `frontend/src-tauri/`,
3) собирает NETFORY MSI с merge-конфигом `src-tauri/tauri.mail.conf.json`
(`bundle.resources: ["oxid-mail.exe"]`) - установщик кладёт `oxid-mail.exe`
в папку установки рядом с exe NETFORY, где его находит `launch_oxid_mail`.

Данные хранятся в `./oxid-data/{STH-адрес}/` (env `OXID_DATA_DIR`; в Tauri по умолчанию -
системный appData), содержимое не читаемо без seed-фразы.

## Gmail: вход по app password (OAuth-кнопка скрыта)

С 2026-06 кнопка **Sign in with Google - 1 click** скрыта по решению пользователя:
единственный путь для Gmail - **пароль приложения** (App Password) по инструкции
под формой (myaccount.google.com/apppasswords). Ядро OAuth (XOAUTH2, refresh_token)
осталось в коде (`oauth.rs`, команда `oauth_gmail_sign_in`) и может быть возвращено
одной кнопкой в UI.

## Флаги на сервер

Прочитанность (\Seen) и звёзды (\Flagged) пушатся на IMAP-сервер при изменении;
удаление из корзины удаляет письмо и на сервере (+\Deleted, EXPUNGE).
Перемещение в корзину - пока локальное. Автопроверка новых писем - каждые 2 минуты,
счётчик непрочитанных показывается в заголовке окна.

## Безопасность и шифрование данных на диске

**Как шифруется почта (sled-хранилище, крейт `mail-store`):**

- Ключ хранилища: `HKDF-SHA256(sha256(mnemonic), salt "oxid-mail/store/v1")` -
  выводится из seed-фразы, сам ключ на диск никогда не пишется.
- Каждое значение в sled (тела писем, JSON аккаунтов с паролями, метаданные):
  `zstd-сжатие -> XChaCha20-Poly1305` со случайным 24-байтовым nonce.
  На диске нет ни одного открытого байта содержимого.
- **Вложения** хранятся так же - отдельными шифрованными blob'ами
  (`put_blob`, дерево `atts:{account}`), расшифровываются только при скачивании.
- Открыть существующее хранилище чужим seed невозможно (маркер `__check__`
  проверяется при открытии; AEAD-аутентификация отвергает неверный ключ).
- Данные лежат в `appData/oxid-data/{STH-адрес}` - у каждой identity свой каталог.

**Как защищён сам seed:**

- Запуск из NETFORY: seed приходит по stdin-IPC и живёт **только в RAM** -
  на диск не записывается вообще, PIN не нужен (авторизация пройдена в NETFORY).
- Автономный запуск: seed можно запечатать PIN-кодом (`pin_seal`) - на диске
  хранится только блоб, зашифрованный тем же XChaCha20-Poly1305 с ключом из PIN;
  без PIN plaintext-seed недоступен.
- Приватный ключ: `sha256(mnemonic)` -> secp256k1; адрес `S…` = base58check(0x3F ‖ ripemd160(pubkey)) -
  идентично NETFORY/SmartHoldem-клиенту.
- Пароли почтовых аккаунтов хранятся только внутри шифрованного хранилища и не покидают устройство.

## Провайдеры (этап 1)

Gmail / Yandex / Yahoo - по **паролю приложения** (app password), Custom IMAP - вручную.
IMAP-логин проверяется в момент добавления аккаунта. OAuth для Gmail - этап 2.

## Что синхронизируется (этап 1)

- INBOX (последние 50 писем) + папка «Отправленные» (30) - pull-only.
- Прочитанность/звёзды/корзина - локальное состояние (не пушится на сервер, этап 2).
- Отправка - SMTP (465 = TLS, иначе STARTTLS), копия сохраняется в Sent локально.
